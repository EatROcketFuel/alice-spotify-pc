# Alice PC Controller

Фоновое приложение для Windows 11: принимает команды Яндекс Алисы через MQTT и управляет
Spotify Desktop, мультимедийными клавишами и аудиовыходом Windows. Живёт в системном трее.

```
Алиса ──► навык «Умный дом» (MQTT-мост) или свой навык Яндекс Диалогов
                │  publish
                ▼
          MQTT-брокер  ◄──── subscribe ──── main.py (трей Windows 11)
                                              ├─ Spotify.exe: запуск / закрытие
                                              ├─ медиаклавиши (SendInput)
                                              ├─ устройство вывода звука (Core Audio)
                                              └─ Spotify Web API: поиск и воспроизведение
```

## 0. Быстрый старт

Требования: Windows 10/11 x64, Python 3.10+ (рекомендуется 3.12), Spotify Desktop,
Spotify Premium (нужен только для поиска и воспроизведения через Web API), MQTT-брокер.

1. Установите Python с https://www.python.org/downloads/ и отметьте **Add python.exe to PATH**.
2. Распакуйте архив в папку без кириллицы и пробелов, например `C:\Tools\alice-spotify-pc`.
3. Запустите `install.bat`.
4. Запустите `settings.bat` — откроется окно настроек:
   - **Подключение**: сервер, порт, логин и пароль MQTT, кнопка «Проверить подключение»;
   - **Звук**: колонка и наушники выбираются из найденных устройств (определяются автоматически
     по названию: «Станция», «JBL», «Наушники»...), режим «только Spotify» или «вся Windows»;
   - **Spotify**: путь к `Spotify.exe`, «Только в трее» (окно Spotify прячется, когда программа
     его запускает или включает трек), число нажатий «назад», режим поиска;
   - **Общие**: «Запускать вместе с Windows», уведомления, подробность лога.
5. `run_console.bat` — проверьте, что в логе есть `MQTT state: connecting -> connected`.
6. Закройте консоль (Ctrl+C) и запустите `run.bat` — появится иконка в трее.
   Двойной щелчок по иконке (или меню → «Настройки...») открывает окно настроек; после
   «Сохранить» программа сама перезапускается с новыми настройками.
   В меню есть «Показать Spotify» / «Спрятать Spotify в трей».

Всё то же самое можно вписать в `config.json` вручную (разделы 1–5), окно лишь редактирует этот файл.

Цвет иконки в трее: зелёный — брокер подключён, жёлтый — подключение, красный — нет связи.
Меню: состояние MQTT и Spotify API, «Переподключить MQTT», «Открыть лог», «Открыть config.json»,
«Открыть папку», «Выход».

> `config.json` сохраняйте в UTF-8 (Блокнот Windows 11 делает это по умолчанию).
> Если JSON сломан, приложение при запуске покажет строку и столбец ошибки.

Проверка без Алисы — команда выполняется локально, без брокера:

```bat
.venv\Scripts\python main.py --test media_control PLAY_PAUSE
.venv\Scripts\python main.py --test spotify_power ON
.venv\Scripts\python main.py --test audio_switch HEADPHONES
.venv\Scripts\python main.py --test spotify_search "Группа крови - Кино"
```

Проверка через брокер (приложение должно быть запущено):

```bat
.venv\Scripts\python main.py --send alice/pc/media/control NEXT
```

## 1. Spotify Developer: Client ID и Client Secret

**Поиск без ключей (по умолчанию, Premium не нужен).** Пока Spotify не авторизован
(`spotify.search_mode: "auto"`) или при `"keyless"`, программа ищет трек через DuckDuckGo
(ссылки `open.spotify.com/track/...`), сверяет название через открытый Spotify oEmbed и открывает
`spotify:track:<id>` в приложении Spotify — клиент сразу начинает играть. Если поиск не ответил
(капча, нет сети), в Spotify открывается страница поиска по запросу. Проверка:
`.venv\Scripts\python main.py --test spotify_search "Группа крови - Кино"`.

Ключи ниже нужны только для поиска через Spotify Web API (`"web_api"`). По правилам Spotify
приложения разработчика работают, только если у владельца есть **Premium**. Питание Spotify,
медиаклавиши и переключение звука работают без ключей.

### 1.1. Создание приложения

1. Откройте https://developer.spotify.com/dashboard и войдите своим аккаунтом Spotify
   (тем же, что в десктопном клиенте).
2. При первом входе примите Developer Terms of Service.
3. Нажмите **Create app** и заполните:
   - **App name**: `Alice PC Controller` (любое);
   - **App description**: `Alice smart home control` (любое);
   - **Redirect URIs**: ровно `http://127.0.0.1:8888/callback` → **Add**;
   - **Which API/SDKs are you planning to use?**: отметьте **Web API**;
   - согласитесь с условиями → **Save**.
4. В приложении откройте **Settings** → **Basic Information**:
   - скопируйте **Client ID**;
   - нажмите **View client secret** и скопируйте **Client Secret**.
5. Вставьте их в `config.json`:

```json
"spotify": {
  "client_id": "ваш_client_id",
  "client_secret": "ваш_client_secret",
  "redirect_uri": "http://127.0.0.1:8888/callback"
}
```

Важно:
- Redirect URI в `config.json` и в Dashboard должен совпадать **символ в символ**.
  Используйте `127.0.0.1`, а не `localhost`: Spotify больше не принимает `localhost` для новых приложений.
- Новое приложение работает в **Development mode**: им может пользоваться владелец и
  пользователи, добавленные в **Settings → User Management**. Для личного использования этого достаточно.
- Client Secret — пароль. Не публикуйте `config.json` и `.spotify_token_cache`.

### 1.2. Разовая авторизация (токен в кэше Spotipy)

Запустите `spotify_auth.bat`:

1. Откроется браузер со страницей входа Spotify → **Agree**.
2. Spotify перенаправит браузер на `http://127.0.0.1:8888/callback?code=...`; временный
   локальный сервер Spotipy примет код, а консоль напишет, что вход выполнен.
3. Токен (вместе с refresh-токеном) сохранится в файл `.spotify_token_cache` рядом с `main.py`.

Дальше приложение обновляет токен само и **никогда** не открывает браузер и не ждёт ввода в
фоне. Если токен отозван или удалён, поиск вернёт ошибку в лог/уведомление, а остальные
функции продолжат работать — просто снова запустите `spotify_auth.bat`.

**Если редирект не срабатывает** (порт 8888 занят, браузер на другом ПК, блокирует антивирус):

```bat
spotify_auth.bat manual
```

Консоль покажет ссылку. Откройте её в любом браузере, войдите, и после перехода на
`127.0.0.1:8888/...` (страница «Не удаётся открыть» — это нормально) скопируйте **полный адрес**
из адресной строки и вставьте в консоль.

> Региональная заметка: если `accounts.spotify.com` не открывается из вашей сети, выполните только
> разовый вход через любую доступную сеть. Дальше нужен лишь доступ к Web API
> (`api.spotify.com`) и обновление токена.

### 1.3. Как работает поиск

Payload `alice/pc/spotify/search`:

| Payload | Что ищется |
|---|---|
| `Группа крови - Кино` | `track:"Группа крови" artist:"Кино"`, затем более мягкие запросы |
| `Bohemian Rhapsody – Queen` | дефисы `-`, `–`, `—` равнозначны |
| `кино звезда по имени солнце` | свободный поиск |
| `https://open.spotify.com/track/...` или `spotify:track:...` | конкретный трек без поиска |

Воспроизведение идёт через Spotify Connect на устройство этого ПК. Если Spotify закрыт и
`auto_launch_on_search: true`, приложение запустит его и подождёт до `device_wait_seconds`, пока
клиент появится в списке устройств. Если у вас несколько устройств, укажите имя ПК в
`spotify.device_name` (точное имя видно в Spotify → значок «Устройства»).

## 2. Связка MQTT-топиков с Яндекс Алисой

### 2.1. MQTT-брокер

Нужен брокер, доступный и из интернета (для навыка Алисы), и с вашего ПК. Варианты:
- брокер, который предоставляет сам навык-мост (у части навыков он встроенный — смотрите их инструкцию);
- облачный брокер (HiveMQ Cloud, EMQX Cloud, WQTT и т. п.);
- свой Mosquitto на VPS/роутере с паролем (и желательно TLS, порт 8883).

Заполните `config.json`:

```json
"mqtt": {
  "host": "broker.example.com",
  "port": 8883,
  "username": "user",
  "password": "password",
  "tls": true
}
```

Приложение использует MQTT 3.1.1, переподключается автоматически (задержка 1→60 с),
после каждого переподключения заново подписывается и публикует `online` в `alice/pc/status`
(retained; при обрыве брокер сам выставит `offline` через Last Will). Старые retained-команды
по умолчанию игнорируются (`ignore_retained: true`), чтобы при запуске ПК не включилось
то, что было отправлено вчера.

### 2.2. Устройства в «Умном доме Яндекса» через навык-мост

Навыки-мосты (например, **Intruder MQTT**, **vvh.space** и аналогичные из каталога навыков
«Умного дома») позволяют создать в личном кабинете навыка виртуальное устройство и указать,
в какой MQTT-топик и с каким значением публиковать команду. Общий порядок:

1. Зарегистрируйтесь на сайте навыка-моста и укажите данные своего брокера
   (или получите данные встроенного брокера и впишите их в `config.json`).
2. Создайте устройства по таблице ниже.
3. В приложении **Дом с Алисой** → **+** → **Устройство умного дома** → найдите навык →
   **Привязать к Яндексу** → войдите → **Обновить список устройств**.
4. Распределите устройства по комнатам и при желании переименуйте.

Точные названия полей в кабинетах разных навыков отличаются; ориентируйтесь на смысл:
«топик команды (command/set topic)» и «значения вкл/выкл (payload on/off)».

| Устройство в Алисе | Тип / умение | Топик команды | Вкл | Выкл |
|---|---|---|---|---|
| «Спотифай» | выключатель (on_off) | `alice/pc/spotify/power` | `ON` | `OFF` |
| «Колонка компьютера» | выключатель (on_off) | `alice/pc/audio/switch` | `SPEAKERS` | `HEADPHONES` |
| «Следующий трек» | выключатель / кнопка | `alice/pc/media/next` | любое | любое |
| «Предыдущий трек» | выключатель / кнопка | `alice/pc/media/prev` | любое | любое |
| «Пауза» | выключатель / кнопка | `alice/pc/media/play_pause` | любое | любое |

Пояснения:
- Если навык умеет слать только `1`/`0` или `true`/`false`, это не проблема: `payload_aliases`
  в `config.json` уже переводит `1/true/on` → `SPEAKERS`, `0/false/off` → `HEADPHONES`.
  Аналогично `ON/OFF` для Spotify принимает `1/0`, `true/false`, `вкл/выкл`.
- Медиакнопки (`button_topics`) срабатывают на **любое** сообщение, поэтому и «включи», и «выключи»
  жмут клавишу. Чтобы реагировать только на «включи», поставьте `"trigger": "on"`.
- Если навык позволяет задать произвольное значение, можно слать всё в один топик
  `alice/pc/media/control` со значениями `NEXT`, `PREV`, `PLAY_PAUSE`.

Голосом: «Алиса, включи Спотифай», «Алиса, выключи колонку компьютера» (звук уйдёт в наушники),
«Алиса, включи следующий трек».

### 2.3. Сценарии Алисы (удобные фразы и любимые треки)

В **Дом с Алисой → Сценарии** создайте сценарий с фразой-активатором и действием над
устройством, например:
- «Алиса, музыку в наушники» → «Колонка компьютера» → выключить;
- «Алиса, дальше» → «Следующий трек» → включить.

«Умный дом» не передаёт произвольный текст, поэтому для конкретных треков используйте
`button_topics` с фиксированным запросом:

```json
{ "topic": "alice/pc/fav/kino", "command": "spotify_search", "payload": "Группа крови - Кино", "trigger": "any" }
```

Создайте устройство-кнопку на топик `alice/pc/fav/kino` и сценарий «Алиса, включи Кино на компьютере».

### 2.4. Свободный голосовой поиск: свой навык Яндекс Диалогов (необязательно)

Для фраз вида «Алиса, попроси Мой компьютер включить Группа крови Кино» в папке
`yandex_dialogs_skill\` лежит готовый вебхук для **Yandex Cloud Functions**.

1. https://console.yandex.cloud → **Cloud Functions** → **Создать функцию**.
2. Среда выполнения **Python 3.12**, способ — **ZIP-архив** или **Редактор кода**: добавьте
   `index.py` и `requirements.txt` из `yandex_dialogs_skill\`. Точка входа: `index.handler`.
   Таймаут 3 с, память 128 МБ.
3. Переменные окружения: `MQTT_HOST`, `MQTT_PORT`, `MQTT_USER`, `MQTT_PASSWORD`, `MQTT_TLS` (`1` для TLS),
   при необходимости `TOPIC_PREFIX` (по умолчанию `alice/pc`).
4. https://dialogs.yandex.ru/developer → **Создать диалог** → **Навык** → бэкенд
   **Функция в Яндекс Облаке** → выберите функцию. Задайте имя активации (например, «Мой компьютер»),
   доступ — **приватный**, отправьте на модерацию/включите тестирование.

Понимаемые фразы: «включи / поставь <трек и исполнитель>», «следующий», «предыдущий», «пауза»,
«на наушники», «на колонку», «запусти спотифай», «выключи спотифай».
Брокер должен быть доступен из интернета. Алиса ждёт ответ около 3 секунд — используйте близкий
к Yandex Cloud брокер.

## 3. Точные имена наушников и колонки

1. Включите и подключите оба устройства (Bluetooth-колонку и наушники).
2. Запустите `list_audio_devices.bat`. Пример вывода:

```
Active playback devices (backend: pycaw):
 * Динамики (Realtek(R) Audio)
   Наушники (WH-1000XM4 Stereo)
   Головной телефон (WH-1000XM4 Hands-Free AG Audio)
   Yandex Station Mini (Яндекс Станция)

Current config.json mapping:
  SPEAKERS     ['Yandex Station'] -> Yandex Station Mini (Яндекс Станция)
  HEADPHONES   ['WH-1000XM4'] -> Наушники (WH-1000XM4 Stereo)
```

`*` — текущее устройство по умолчанию. То же имя видно в **Параметры → Система → Звук → Вывод**
или в `mmsys.cpl` (Win+R) на вкладке **Воспроизведение**.

3. Скопируйте имя целиком или его уникальную часть в `config.json`:

```json
"audio": {
  "devices": {
    "SPEAKERS":   ["Yandex Station", "Динамики (Realtek(R) Audio)"],
    "HEADPHONES": ["WH-1000XM4"]
  }
}
```

Правила поиска:
- регистр не важен; сначала точное совпадение, потом подстрока;
- в списке можно указать несколько вариантов — используется первый **подключённый**
  (удобно: «колонка, а если она выключена — встроенные динамики»);
- Bluetooth-профиль `Hands-Free` (моно, низкое качество) пропускается, если есть Stereo-вариант;
- переименовать устройство можно в `mmsys.cpl` → **Свойства**; потом обновите `config.json`.

4. Проверьте: `.venv\Scripts\python main.py --test audio_switch HEADPHONES`.

**Что именно переключается — `audio.mode`:**

- `"app"` (по умолчанию) — переключается **только Spotify**, системный звук и остальные программы
  остаются на текущем устройстве Windows. Это то же самое, что «Параметры → Система → Звук →
  Микшер громкости → Spotify → Устройство вывода». Делает это NirSoft SoundVolumeView
  (`tools\SoundVolumeView\`, уже в архиве; бесплатная утилита без цифровой подписи, поэтому
  SmartScreen/антивирус может спросить разрешение). Windows запоминает выбор для Spotify и после
  перезапуска. Если Spotify в момент команды не запущен, выбор применится, когда Алиса его включит.
  Список программ — `audio.app_routing.processes`.
- `"system"` — меняется устройство по умолчанию всей Windows для ролей из `audio.roles`.

Вернуть Spotify на системное устройство: в микшере громкости выберите для Spotify «По умолчанию».

**Запасной бэкенд PowerShell.** Если pycaw не работает, выполните
`powershell -ExecutionPolicy Bypass -File scripts\install_audiodevicecmdlets.ps1` и поставьте
`"backend": "powershell"` (по умолчанию `auto` — сначала pycaw, потом PowerShell).

**`audio.app_routing.enabled`** нужен только в режиме `"system"`: тогда программы из `processes`
дополнительно перенаправляются через SoundVolumeView (если они были закреплены за устройством).

## 4. Автозапуск вместе с Windows

**Способ 0 (проще всего).** Окно настроек → «Общие» → «Запускать вместе с Windows» (создаёт тот же ярлык).

**Способ 1.** Запустите `add_to_startup.bat`. В папке автозагрузки
(`Win+R` → `shell:startup`) появится ярлык `Alice PC Controller.lnk`, который запускает
`.venv\Scripts\pythonw.exe main.py` без консоли. Убрать — `remove_from_startup.bat`.

**Способ 2 (вручную).** `Win+R` → `shell:startup` → **Создать → Ярлык**:
- Объект: `C:\Tools\alice-spotify-pc\.venv\Scripts\pythonw.exe "C:\Tools\alice-spotify-pc\main.py"`
- Рабочая папка: `C:\Tools\alice-spotify-pc`

**Способ 3 (Планировщик заданий).** Для запуска с задержкой: `taskschd.msc` → **Создать задачу** →
триггер **При входе в систему** (задержка 30 с) → действие — программа `pythonw.exe` из `.venv`,
аргумент `"...\main.py"`, рабочая папка — папка проекта. Не включайте «Выполнять с наивысшими
правами» без необходимости и не запускайте «независимо от входа пользователя»: трею и медиаклавишам
нужен интерактивный сеанс пользователя.

Повторный запуск безопасен: второй экземпляр увидит первый (именованный mutex) и завершится.

Чтобы Windows не прятала иконку: **Параметры → Персонализация → Панель задач → Другие значки в
области уведомлений** → включите `pythonw.exe` / Alice PC Controller.

## 5. Справочник

### Топики команд

| Топик | Payload | Действие |
|---|---|---|
| `alice/pc/spotify/power` | `ON` / `OFF` | Запуск `%APPDATA%\Spotify\Spotify.exe --minimized` / корректное закрытие (WM_CLOSE, затем terminate по таймауту) |
| `alice/pc/media/control` | `NEXT`, `PREV`, `PLAY_PAUSE`, `STOP`, `MUTE`, `VOLUME_UP`, `VOLUME_DOWN` | Аппаратная медиаклавиша (Win32 `SendInput`) — работает в свёрнутом Spotify и в полноэкранных играх |
| `alice/pc/audio/switch` | `SPEAKERS` / `HEADPHONES` (или любой ключ из `audio.devices`) | Смена устройства вывода по умолчанию |
| `alice/pc/spotify/search` | `Песня - Исполнитель` | Поиск через Web API и воспроизведение на этом ПК |
| `alice/pc/media/next`, `.../prev`, `.../play_pause` | любое | Кнопки для навыков, умеющих только вкл/выкл |

Payload нечувствителен к регистру; пробелы и дефисы допускаются (`play pause`, `play-pause`).

### Топики состояния (публикует приложение)

| Топик | Значение |
|---|---|
| `alice/pc/status` | `online` / `offline` (retained, Last Will) |
| `alice/pc/state/spotify` | `ON` / `OFF` |
| `alice/pc/state/audio` | ключ выбранного устройства, например `HEADPHONES` |
| `alice/pc/state/track` | `Исполнитель — Трек` после поиска |
| `alice/pc/state/error` | текст последней ошибки |

Их можно подключить в навыке-мосте как топики состояния устройств.

### Параметры командной строки

| Команда | Назначение |
|---|---|
| `main.py` | трей (обычный режим) |
| `main.py --no-tray` | консоль, без трея |
| `main.py --auth` / `--auth-manual` | вход в Spotify |
| `main.py --list-devices` | устройства вывода звука |
| `main.py --test КОМАНДА PAYLOAD` | выполнить команду локально (`spotify_power`, `media_control`, `audio_switch`, `spotify_search`) |
| `main.py --send ТОПИК PAYLOAD` | отправить сообщение в брокер |
| `main.py --config путь.json` | другой файл конфигурации |

### config.json

| Ключ | Описание |
|---|---|
| `mqtt.host`, `port`, `username`, `password` | брокер |
| `mqtt.tls`, `tls_insecure`, `ca_certs` | TLS (обычно порт 8883); `ca_certs` — путь к CA, если сертификат самоподписанный |
| `mqtt.client_id` | пусто = `alice-pc-<имя ПК>` |
| `mqtt.qos`, `keepalive`, `reconnect_min_delay`, `reconnect_max_delay` | надёжность и переподключение |
| `mqtt.ignore_retained` | игнорировать старые retained-команды |
| `mqtt.status_topic`, `state_prefix` | топики статуса |
| `topics.*` | имена топиков команд (можно поменять префикс) |
| `button_topics[]` | `topic`, `command`, `payload`, `trigger` (`any` / `on`) |
| `payload_aliases.<команда>` | перевод значений моста в команды |
| `spotify.exe_path`, `launch_args`, `process_name` | запуск клиента; для версии из Microsoft Store укажите путь к её `Spotify.exe` |
| `spotify.close_timeout_seconds`, `pause_before_close` | корректное закрытие (и пауза перед ним) |
| `spotify.search_mode` | `auto` / `keyless` (без ключей) / `web_api` (ключи + Premium) |
| `spotify.tray_only` | `true`: прятать окно Spotify, когда программа его запускает или включает трек (остаётся значок в трее) |
| `spotify.warmup_seconds` | сколько секунд Spotify, запущенный в трее, показывается невидимым окном, чтобы начал играть (по умолчанию 4) |
| `spotify.play_on_launch` | `true`: после «включи Спотифай» сразу нажать Play |
| `spotify.prev_presses` | сколько раз нажимать «назад» (2: первое нажатие Spotify перематывает трек в начало) |
| `spotify.client_id`, `client_secret`, `redirect_uri`, `cache_path` | Web API и кэш токена |
| `spotify.device_name`, `market`, `auto_launch_on_search`, `device_wait_seconds` | выбор устройства Connect и поиск |
| `audio.backend` | `auto` / `pycaw` / `powershell` |
| `audio.devices` | логическое имя → список имён/подстрок Windows |
| `audio.mode` | `app` — только Spotify, `system` — вся Windows |
| `audio.roles` | `console`, `multimedia`, `communications` |
| `audio.app_routing` | SoundVolumeView для отдельных программ |
| `logging.level`, `file`, `max_bytes`, `backup_count` | лог с ротацией (`logs\alice_pc.log`) |
| `tray.notifications` | всплывающие уведомления Windows |

Ключи, начинающиеся с `_`, считаются комментариями. Отсутствующие ключи берут значения по умолчанию.

## 6. Диагностика и частые проблемы

Сначала откройте лог: меню трея → «Открыть лог» (`logs\alice_pc.log`) или запустите `run_console.bat`.

| Симптом | Решение |
|---|---|
| Иконка красная, `broker unreachable` | Проверьте `host`/`port`/TLS, доступность брокера и брандмауэр. Приложение переподключится само |
| `Not authorized` / `Bad user name or password` | Логин/пароль брокера; права на `alice/pc/#` |
| Команды не приходят | Сверьте топики в навыке и `config.json` (регистр важен). Проверьте `main.py --send ...` |
| `Spotify token is missing or revoked` | `spotify_auth.bat` |
| `INVALID_CLIENT: Invalid redirect URI` | Redirect URI в Dashboard и `config.json` должны совпадать: `http://127.0.0.1:8888/callback` |
| `No active Spotify device` | Запустите Spotify и войдите в аккаунт; проверьте `device_name`; увеличьте `device_wait_seconds` |
| `PREMIUM_REQUIRED` | Управление воспроизведением через Web API доступно только с Premium |
| Spotify не найден | Укажите полный путь в `spotify.exe_path` (версия из Microsoft Store ставится в другое место) |
| `No playback device matches` | `list_audio_devices.bat`, устройство должно быть подключено; скопируйте имя |
| Медиаклавиши не действуют в игре с админ-правами | Windows блокирует ввод из обычного процесса в процесс с повышенными правами. Запустите приложение с теми же правами |
| Два экземпляра | Второй завершается сам; проверьте `pythonw.exe` в диспетчере задач |
| Кракозябры в консоли | Косметика консоли; файлы и лог в UTF-8 |

Подробный лог: `"level": "DEBUG"` в `config.json`.

### Безопасность

- `config.json` (пароль брокера, Client Secret) и `.spotify_token_cache` — секреты; не выкладывайте их.
- Используйте брокер с паролем и TLS; не открывайте анонимный брокер в интернет.
- Приложение выполняет только перечисленные команды — произвольные программы или скрипты по MQTT не запускаются.
